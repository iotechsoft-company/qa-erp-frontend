## วิธีอ่านสถานะ

- **ทำแล้ว** = มี assertion ใน spec สำหรับขอบเขตที่ระบุ ไม่ได้หมายถึง flow ทั้งหมดเสร็จ
- **บางส่วน** = มี happy path/validation บางขั้น แต่ยังขาดผลข้างเคียงหรือทางเลือก
- **ยังขาด** = ยังไม่มี assertion สำหรับพฤติกรรมนั้น การเปิด route ได้หรือใช้ API เป็น setup/cleanup ไม่นับเป็น workflow coverage
- **บั๊กขวาง** = มี issue และ regression ยืนยันอาการเฉพาะ; เทสผ่านเมื่อยังพบอาการนั้น ไม่ใช่ healthy flow ผ่าน
- **quarantined** = `test.fixme` ไม่ได้รัน; ห้ามนับเป็น coverage ที่ผ่าน

UI/API ในตารางหมายถึงขั้นที่มี assertion จริง ผล stock/บัญชีระบุแยกในคอลัมน์เดียวกันเพื่อลดการตีความเกินหลักฐาน สถานะ issue เดิมทั้งเก้ารายการเป็น baseline เมื่อ 2026-11-15; P1.1 เพิ่ม api#18 เมื่อ 2026-11-16 แต่ frontend#3/#4 มี deployed fix จาก frontend PR #1 และ healthy regressions แล้ว (ดู B1–B3); issue annotation ไม่ได้แปลว่ายังถูกบล็อกเสมอ ผลรันเดิมเป็น baseline ของเอกสาร; การเพิ่ม P0.2 Receiving และผลตรวจใหม่แยกไว้ใน ROADMAP
